# t0-gamma zero-shot forecaster

SolarCast's second TSFM is **`theforecastingcompany/t0-gamma`**, selected before
implementation in the [landscape review](tsfm-landscape.md). This adapter uses only
historical national PV, without fitting, weather, capacity, Elia forecasts,
engineered features or test-period adaptation. The shared forecasting contracts,
backtester and common-support evaluator remain unchanged. Technical integration and the [controlled zero-shot comparison](../experiments/tsfm-zero-shot-v1.md)
are documented separately.

with causal time-axis and variate-axis attention and native causal mean/std plus
arcsinh scaling. Chronos-2 uses an encoder-only architecture (~120M parameters).

and uses raw native P50 for both. These are capability differences, not accuracy
claims. The gamma weight artifact is 1,022,492,908 bytes; download size is not a
measurement of process RAM or peak device memory.

## Installation and use

For the released package, use `python -m pip install "solarcast-belgium[t0]"`.
For source development, install from this repository:

```powershell
python -m pip install -e ".[t0]"
# Development checks:
python -m pip install -e ".[dev,t0]"
# Independent alternative for Candidate #1:
python -m pip install -e ".[dev,chronos]"
```

The `t0` extra adds `tfc-t0[torch]>=0.6.1,<0.7`. It does not require Chronos or
Transformers. Shared transitive Torch/Hub dependencies are resolved by pip, without
duplicated framework requirements in SolarCast metadata. Installing
`".[dev,t0,chronos]"` is supported in the tested environment; no combined `tsfm`
extra is needed. Select a suitable CPU/CUDA wheel using the
[official PyTorch instructions](https://pytorch.org/get-started/locally/).

```python
from solarcast.models.t0 import T0Config, T0Forecaster

model = T0Forecaster(T0Config(context_length=1344, device="cpu"))
model.load()  # Optional warm-up; first predict also loads.
forecast = model.predict(context)  # Existing ForecastContext.
```

`import solarcast`, data, backtesting, evaluation and adapter module imports do
not import Torch, t0 or Chronos. Constructing the forecaster checks optional
imports and gives the correct installation hint if missing; it does not fetch
weights. A successful `load()` is reused across origins. Loading failures retain
their causes and may be retried. Metadata records stable `model_id="t0"`, exact
checkpoint/revision, library version, context cap, device, dtype and adjustments.

## Context, frequency and missingness

Input is one NumPy float32 batch shaped **[1, elapsed context slots]** from the
copied ForecastContext PV history. Only completed eligible intervals supplied by
that context are accessible. Optional `context.features` is ignored. No dataset
lookup, fitted custom scaler or future covariate path exists in this adapter.

The maximum context defaults to **1344** elapsed 15-minute slots. A common 7D cap
is 672. SolarCast allows integer caps **1–8192** as a resource guard; **8192 is not
a verified gamma-specific hard maximum**. Upstream validates context length
against input width and handles patch padding internally, without publishing a
gamma-specific hard context cap in the checked config. Broader long-context
performance is unverified; do not interpret the guard as evidence that every
context length is equally useful.

Keep the same history selection/window as Chronos for a common-context experiment.
The issue-anchored 14D window with 30-minute safety lag supplies **1342** slots,
not 1344; the adapter cannot reach outside that window to obtain two older rows.
It keeps starts >= cutoff minus the cap, then constructs a regular grid from the
earliest retained supplied row through cutoff exclusive. Shorter supplied history
stays shorter: there is no backward extension or silent retrieval.

The array API is frequency agnostic: adjacency represents **15 elapsed minutes**
because SolarCast validates timestamps and reconstructs the regular UTC grid.
No frequency token, hourly resampling or local-naive timestamps are used.
Brussels time is used only by the common target policy.

Explicit nulls, absent interior rows and trailing gaps stay **NaN**. Upstream reads
these as MISSING observations, distinct from its internal PAD cells. No explicit
mask is needed for this single univariate array. Leading supplied missing slots
are preserved too: `trim_leading_missing=False`. There is no interpolation,
forward-fill, zero-fill or custom normalization. Native preprocessing handles
missing values and scaling. Empty/out-of-window/all-NaN history and observations
overflowing float32 fail clearly before loading. One finite observation is the
adapter's minimum, not a claim of adequate forecasting information.

## Forecast lengths, point output and raw behavior

The model can directly request arbitrary positive horizons through **1024 steps
per pass**. Upstream supports autoregressive rollout beyond this; SolarCast
deliberately limits this first adapter to a single block. The full bridge, not
only the target count, must fit that limit. Unsupported requests fail; SolarCast
does not pad, interpolate or duplicate outputs.

For issue 11:00 Brussels and cutoff 10:30, the model starts forecasting at cutoff:

| Next Brussels day | Requested targets | Complete rollout |
|---|---:|---:|
| Spring DST | 92 | 146 |
| Normal | 96 | 150 |
| Autumn DST | 100 | 154 |

The adapter selects exact requested UTC timestamps from the complete rollout,
including sparse requested target sets. Forecast issue time and MW units follow
the common contract. Gaps never shift the forecast anchor backward.

`predict(..., quantile_levels=[0.5])` returns native **P50** in a quantile tensor
shaped [1, rollout, 1]. SolarCast validates shape and finite floating output over
the entire bridge, then extracts that quantile. It does not select a statistic
using test errors. Native 21 quantiles, interpolation and tail extrapolation could
support future probabilistic work; the adapter exposes only deterministic P50.

All optional forecast adjustments are explicitly disabled:
`trim_leading_missing`, `symmetric_averaging`, `clip_nonnegative`, `snap_integers`,
and `drop_constant_covariates`. The last flag is irrelevant without covariates but
is recorded explicitly. No negative clipping, nighttime zeroing or integer
rounding is applied. Native `predict` runs in `torch.inference_mode`; the adapter
also calls `eval()` and disables parameter gradients. No fit/fine-tuning occurs.

## Timing, devices and failures

Explicit devices are `cpu`, `cuda` or `cuda:N`. CPU float32 is the default; CUDA
requests fail clearly when CUDA is unavailable, with no silent fallback. Upstream
uses ordinary PyTorch device paths and separately provides MLX for Apple silicon;
SolarCast does not expose MLX or invent an automatic cross-framework device layer.
Upstream packaging lists Linux/macOS, **not an explicit Windows support promise**.

Hub cache resolution/download and local construction/device transfer are timed
separately. Per-call inference includes the native call and CPU output transfer,
with device synchronization before/after, matching Chronos's timing scope.
It excludes input-grid preparation, download, loading, and process startup/imports.
`last_inference` records slot/missing counts and complete/requested horizon sizes,
and resets before each attempt to avoid stale success diagnostics.

Errors include issue/cutoff/context/rollout information and preserve the cause.
The unchanged backtester with `on_error="continue"` retains failed-origin rows;
the evaluator reports availability and scores common support. No model-specific
engine branch or metric was introduced. Instances assume sequential use.

## Assumptions and limitations

This track assumes regular quarter-hour history, native P50 and sequential local
inference. Historical publication/revision vintages and Elia pretraining exclusion
remain unresolved. A safety lag does not establish an operational information set.
Gamma's hard context ceiling and full training-corpus details remain unverified.
No native GPU/MLX, real-model DST, peak RAM/VRAM or broad Python-version validation
was performed. Offline DST tests and the documented native horizon establish
alignment, not forecast quality. Native missing-value acceptance does not imply
useful predictions from sparse history. Common-context comparisons, all-model
accuracy results belong to the [controlled zero-shot experiment](../experiments/tsfm-zero-shot-v1.md);
any native-context comparison requires a separate disclosed study.
